**VCS** - version control system

Git сохраняет все объекты в свою БД по хеш-сумме содержимого файла

***Хеш сумма*** - *уникальный итентификатор, который вычисляется для любого сохраненного объекта с помощью SHA-1. Любое изменение будет отслежено*

<p align=center><b> 3 состояния Git-файла:
</b> </p>

1. ***Изменен***(*modified*) - файл изменен, но изменения не зафиксированы
2. ***Индексирован***(*staged*) - измененный файл отмечен для включения в коммит
3. ***Зафиксирован***(*commited*) - файл сохранен в локальной сети


   

# Некоторые команды для начала работы:


***Проверка наличия Git в ОС***

git --version



***Посмотреть все установленные настройки и узнать место их хранения***

git config --list --show-origin



***Указать имя пользователя и почту - обязательно для Git коммит***



git config --global user.name input_USER_NAME

git config --global user.email input_EMAIL

***Выбор текстового редактора***

git config --global core.editor EDITOR_NANE(например, Nano)



***Настройка ветки по умолчанию***

При инициализации *git init*, Git создает ветку с именем master - по умолчанию!!!

git config --global init.defaultBranch какая_ветка(например, main)



***Проверка настроек***

git config --list



***Доп информация(помощь) по определенной команде***

1. **Полная информация:** git help название_команды
2. **Короткая выдержка:** git название_команды -h



***Создание репозитория в существующем каталоге***

*Открвываем путь к файлу и тд:*

cd путь/к/файлу

*Инициализация Git:*

git init



***Клонирование существующего репозитория***

Клонирование - скачивание файлов из удаленного сервера(например, Github, GitLab)

Скачивание по умолчанию, без изменений названия каталога:

git clone URL_ADDRESS

Скачивание с изменением имени каталога:

git clone URL_ADDRESS CATALOG_NAME



***Определение статуса файлов***

git status



***Команда,  создает файл с конкретной текстовой информацией***

echo текст > название_файла_куда_записать_текст



***Индексация измененных файлов***

Если хочется внести изменения в файл до коммита, можно воспользоваться командой:

>>>название_редактора file_name

>>>git status

После этого нужно добавить файл, чтобы Git отслеживал его:

git add FILE_NAME



***Сокращенный вывод статуса***

git ststus -s 

     Пример вывода:

     *M  README
     MM  Somefile
     A   lib/git.rb
     M   lib/simplegit.rb
     ??  LICENSE.txt*

***??*** - *неотслеживаемые файлы*
***A*** - *отслеживаемые файлы(**added**)*
***M*** - *отредактированные файлы(**modified**)*


***Игнорирование файлов***

1 способ(*В **.gitignore** нужно добавить файлы, которые нужно игнорировать, которые не должны попасть в Git*):

cat .gitignore


2 способ, если файл добавлен в Git

git rm --catched file_name



***Просмотр индексированных и неиндексированных изменений***

Просмотр проиндексированных элементов, которые войдут в коммит

либо git diff --staged

либо git diff --cached

Непроиндексированные элементы:

git diff



***Коммит изменений***

git commit  -> *направляет в текстовый редактор, необходимо оставить комментарий*

При помощи данной команды можно сразу же закомментировать коммит:

git commit -m "Комментарий"


***Игнорирование индексации***

Можно и без команды *add* перейти к коммиту

git commit -a -m "Комментарий"



***Удаление файлов***

rm FILE_NAME

если файл проиндексирован, добавлен в Git:

git rm --cached FILE_NAME/



***Просмотр истории коммитов***

Если запустить команду в каталоге клонированного проекта, можно увидеть историю коммитов, новые коммиты в начале

git log


Введя дополнительные аргументы --p или --patch(показывает разницу в коммитах) и числовой параметр - число записей, можно вывести определенное число коммитов:

git log --p -2 - Выведет 2 коммита

Дополнительный параметр --stat показывает список и количетво измененных файлов, а ткже строк в каждом из файлов было добавлено либо удалено. В конце резюмирует изменения, которые произошли

git log --stat

Параметр --pretty=аргумент, выводит в одну строку коммит, комментарий - не самая полезная опция. В качестве аргумента можно передать ***format***, который может на выводе вывести нужную информацию(хеш коммта, хеш дерева, имя автора, электронная почта, содержание и тд)

git log --pretty=oneline



***Ограничение вывода***

Можно указать вренные ограничения(ЧИСЛО.(weeks, days, years)

git log --since=2.weeks


# Операции отмены

***Отмена коммита*** 

git commit --ammend


***Отмена индексации файла***

git reset Название_Файла


***Отмена изменений в файле***

Откат до предыдущего(первоначальное состояние до измений) коммита, не хочется сохранять свои изменения

git restore --staged НАЗВАНИЕ_ФАЙЛА


# Работа с удаленными репозиториями

***Просмотр удаленных(сетевых) репозиториев***

Выводит список удаленных репозиториев

git remote

Вывод адресов(URL) удаленных репозиториев:

git remote -v


***Добавление удаленных репозиториев***

git remote add BRANCH_NAME URL_АДРЕС   - adr - сокращенное название URL_АДРЕСА, так будет удобнее с пользоваться 

git remote -v

Получить изменения, которых нет

git fetch ADR      ADR - сокращенное название URL_АДРЕСА



***Получение изменений из удаенного репозитоия - Fetch и Pull***

git fetch ADR или origin          ADR - сокращенное название URL_АДРЕСА

**origin - при клонировании git clone url, Git автоматически добавляет удаленный репозиторий под имененм origin**


***Отправка изменений в удаленный репозиторий(Push)***

git push НАЗВАНИЕ_РЕПОЗИТОРИЯ НАЗВАНИЕ_ВЕТКИ

git push origin master 


***Просмотр удаленного репозитория***

git remote show origin


***Удаление и переименование удаленных репозиториев***

```
git remote rename ADR ADDRESS
```
  - изменение названия удаленного репозитория ADR на ADDRESS

```

git remote remove ADDRESS
```
   - Удаляет удаленный репозиторий


# Ветвление в Git

Ветвление позволяет вносить изменения в код, не затрагиваю основную версию программы. Позволяет одновременно разработчикам создавать собственные ветки и работать над проектом. Использование веток помогает организовывать выпуск обновлений

В конце, для объединения новой ветки с основной нужно их объединить(замерджить)



***Создание новой ветки***
```
git branch НАЗВАНИЕ_ВЕТКИ
```

***Переключение веток***
```
git checkout НАЗВАНИЕ_ВЕТКИ
```
или
```
git switch BRANC_NAME
```


***Одновременное создание новой ветки и переключение на нее***
```
git checkout -b BRANCH_NAME
```
или
```
git switch -c BRANCH_NAME
```
-c, --create



***Слияние ветки с основной***
```
git checkout MAIN_BRANCH_NAME
git merge MERGING_BRANCH_NAME
```

***Удаление ветки***
```
git branch -d BRANCH_NAME
```

***Управление ветками***
***Показавть имеющиеся ветки***
```
git branch
```

***Посмотреть последний коммит на каждой из веток***
```
git branch -v
```

***Посмотреть ветки, которые были слиты/не слиты с текущей веткой***
```
git branch --merged
```
не слитые:
```
git branch --merged
```


***Переименование ветки**

Локальное переименование ветки:
```
git branch --move CURRENT_BRANCH_NAME NEW_BRANCH_NAME
```

Изменение названия ветки на удаленном сервере:
```
git push --set-upstream origin NEW_BRANCH_NAME
```
