**VCS** - version control system

Git сохраняет все объекты в свою БД по хеш-сумме содержимого файла

***Хеш сумма*** - *уникальный итентификатор, который вычисляется для любого сохраненного объекта с помощью SHA-1. Любое изменение будет отслежено*

<p align=center><b> 3 состояния Git-файла:
</b> </p>

1. ***Изменен***(*modified*) - файл изменен, но изменения не зафиксированы
2. ***Индексирован***(*staged*) - измененный файл отмечен для включения в коммит
3. ***Зафиксирован***(*commited*) - файл сохранен в локальной сети


   

Некоторые команды для начала работы:


***Проверка наличия Git в ОС***

git --version



***Посмотреть все установленные настройки и узнать место их хранения***

git config --list --show-origin



***Указать имя пользователя и почту - обязательно для Git коммит***



git config --global user.name input_USER_NAME

git config --global user.email input_EMAIL

***Выбор текстового редактора***

git config --global core.editor EDITOR_NANE(например, Nano)



***Настройка ветки по умолчанию***

При инициализации *git init*, Git создает ветку с именем master - по умолчанию!!!

git config --global init.defaultBranch какая_ветка(например, main)



***Проверка настроек***

git config --list



***Доп информация(помощь) по определенной команде***

1. **Полная информация:** git help название_команды
2. **Короткая выдержка:** git название_команды -h



***Создание репозитория в существующем каталоге***

*Открвываем путь к файлу и тд:*

cd путь/к/файлу

*Инициализация Git:*

git init



***Клонирование существующего репозитория***

Клонирование - скачивание файлов из удаленного сервера(например, Github, GitLab)

Скачивание по умолчанию, без изменений названия каталога:

git clone URL_ADDRESS

Скачивание с изменением имени каталога:

git clone URL_ADDRESS CATALOG_NAME



***Определение статуса файлов***

git status



***Команда,  создает файл с конкретной текстовой информацией***

echo текст > название_файла_куда_записать_текст



***Индексация измененных файлов***

Если хочется внести изменения в файл до коммита, можно воспользоваться командой:

>>>название_редактора file_name

>>>git status

После этого нужно добавить файл, чтобы Git отслеживал его:

git add FILE_NAME



***Сокращенный вывод статуса***

git ststus -s 

     Пример вывода:

     *M  README
     MM  Somefile
     A   lib/git.rb
     M   lib/simplegit.rb
     ??  LICENSE.txt*

***??*** - *неотслеживаемые файлы*
***A*** - *отслеживаемые файлы(**added**)*
***M*** - *отредактированные файлы(**modified**)*


***Игнорирование файлов***

1 способ(*В **.gitignore** нужно добавить файлы, которые нужно игнорировать, которые не должны попасть в Git*):

cat .gitignore


2 способ, если файл добавлен в Git

git rm --catched file_name



***Просмотр индексированных и неиндексированных изменений***

Просмотр проиндексированных элементов, которые войдут в коммит

либо git diff --staged

либо git diff --cached

Непроиндексированные элементы:

git diff



***Коммит изменений***

git commit  -> *направляет в текстовый редактор, необходимо оставить комментарий*

При помощи данной команды можно сразу же закомментировать коммит:

git commit -m "Комментарий"


***Игнорирование индексации***

Можно и без команды *add* перейти к коммиту

git commit -a -m "Комментарий"


***Удаление файлов***

rm FILE_NAME

если файл проиндексирован, добавлен в Git:

git rm --cached FILE_NAME
